## Findings addressed

- Chord rails select the first label that fits each desktop/mobile row, even
  when the key center begins on the last beat of the preceding bar.
- Ear training returns after scoring preparation if the route was destroyed.
  Its pending play handler also returns before loading or starting playback.
- Reused tune-practice routes clear selected retry spots and refusal state when
  changing tunes.
- Ear-training recording metadata records `scoreSource: 'live' | 'replay'`.
  The replay marker commits with the authoritative notes and score. The browser
  test waits for this persisted marker rather than the earlier visible score.
- The shared Musicality audit scope no longer advertises a device-local
  Original rollback. The related inner-motion scope already described automatic
  fallback correctly.
- The security walkthrough's preventive proposal is implemented: recorder
  handles explicitly reject repeated starts, preventing accidental reuse of a
  previous take's scoring audio. Production callers already create one handle
  per take.
