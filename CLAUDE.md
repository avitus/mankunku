This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```sh
npm run dev            # Dev server at http://localhost:5173
npm run build          # Production build (SvelteKit Node adapter → build/)
npm run preview        # Preview production build locally
npm run check          # TypeScript + svelte-check
npm run check:watch    # Type checking in watch mode
npm test               # Unit + integration tests (Vitest)
npm run test:watch     # Vitest watch mode
npm run test:e2e       # Playwright E2E tests
npx vitest run tests/unit/music/scales.test.ts   # Run a single test file
cd omr && uv run pytest                          # OMR subsystem tests (Python, hermetic)
cd omr && uv run pytest -m omr_integration       # OMR real-model tests (downloads 429MB, needs HF auth)
```

CI pipeline (CircleCI): test → (build, db-migrate) → deploy (main branch only). Deploy rsyncs to a Digital Ocean server and restarts via PM2; db-migrate runs `supabase link` + `supabase db push --linked` against the production database, authenticated via the `SUPABASE_ACCESS_TOKEN` env var (no DB password needed).

`deploy/app/release.sh` runs **on the server** and is covered by `npm run test:deploy` (`deploy/app/release.test.sh`, wired into the `test` job — it stubs npm/pm2/curl onto PATH, so it runs anywhere; the deploy-lock tests need `flock` and skip on macOS). Four invariants it exists to protect, all learned from incidents:
- **Dependencies are shared, not per-release.** `npm ci` peaks near 500MB installing 378MB/22k files on a 961MB droplet — it was OOM-killed on 2026-08-07/08 while the lockfile was byte-identical across all three deploys. Deps now install once into `shared/deps` and symlink into each release, keyed on **both** the lockfile and the Node version (`.installed-package-lock.json` + `.installed-node-version`, written only after a successful install so a killed one can't look satisfied). Node is part of the key because native bindings compile against an ABI the lockfile says nothing about — without it, a Node upgrade would silently reuse a tree built for the old runtime. Tradeoff: rolling `current` back gives that release the newer deps.
- **A failed deploy removes its own staged release** — unless `current` already points at it, in which case that dir *is* production and deleting it would turn a failed deploy into an outage. Cleanup unlinks `node_modules`, never follows it into `shared/deps`.
- **`pm2 start` returning 0 is not a deploy.** It only means the process spawned. release.sh polls `/api/health` and compares the **release id**, since a stale process still holding the port answers 200 happily; the deploy job then re-checks the public URL for the commit SHA.
- The droplet has **2GB swap** (added 2026-08-08) because the box has no headroom for burst allocations.

### Database migrations

Create new migrations with `npx supabase migration new <name>`, which produces the Supabase-standard `<YYYYMMDDHHMMSS>_<name>.sql` UTC-timestamp filename. **Do not hand-number new migrations.** Migrations `00001`–`00023` use a legacy sequential scheme; the Supabase dashboard derives its "inserted at (UTC)" column by parsing the version string as a timestamp, so those legacy ones render "Unknown" forever. Renaming them retroactively would require rewriting the `version` primary keys in production's `supabase_migrations.schema_migrations` in lockstep — if files and table rows disagree, the CLI treats every migration as pending and CI's db-migrate job fails. So the legacy names stay; only new ones get real dates. Mixed schemes order correctly, since `00023` sorts before any `2026…` string.

`user_licks.mode` (TEXT NULL, 'major'|'minor'; NULL = not stated) rides FOUR hand-written mappers — `user-licks.ts` `cloudRowToPhrase`/`phraseToRow`, `community.ts` `rowToPhrase`, `sync.ts` `toRow` — and the reconcile is whole-row LWW, so a mapper that forgets the column writes NULL and erases the mode on the next pull (each mapper has a test). `src/lib/supabase/types.ts` is **hand-maintained**, not generator output — edit it by hand when a migration changes the schema, then run `npm run db:types:check` (needs the local stack) to verify it matches the database. There is deliberately no regenerate-in-place script: generating over it drops the source-interface mapping in its header, adds the unused `graphql_public` schema, and widens `public_lick_authors.id` to `string | null`, which would widen the Map key type at three call sites in `persistence/community.ts` for a NOT NULL primary key.

The CLI is linked to the **production** project ref. Local commands need an explicit `--local` (`npx supabase migration up --local`); the `--linked` variants target production. `npm run db:reset` defaults to local but rebuilds from scratch, so prefer `migration up --local` to apply pending migrations in place.

## Architecture

Mankunku is a jazz ear training PWA. It plays a phrase, the user plays it back on their instrument via microphone, and it scores pitch/rhythm accuracy in real time. Built with SvelteKit 2, Svelte 5 (runes), TypeScript strict mode, Tailwind CSS 4, Tone.js, and Pitchy.

### Core module boundaries (`src/lib/`)

- **types/** — Pure TypeScript interfaces grouped by domain. No runtime code.
- **music/** — Pure functions for music theory (scales, intervals, keys, transposition, chords) and engraving policy: `notation.ts` (phrase → ABC with the minor key table — `signatureAccidentalsFor`/`keyLabel`/`abcKeyField`: a minor lick is keyed by its TONIC + `Phrase.mode`, drawn with the relative major's signature (six flats for Eb minor, labelled Ebm; Ab/Db minor label G#m/C#m), `K:Dm`; `mode.ts` owns `lickMode` = explicit `mode` › harmony's tonic segment › major, NEVER the category, because legacy user licks in minor categories were entered with key = relative major; also the ONE enharmonic policy — `spellingContextAt` + `resolveUseFlats`: explicit › key signature › the segment's declared scale, which settles only the chord tier's three ambiguous degrees b3/#9, b5/#11, #5/b13 › governing chord › key default — shared by the chart and every note-name display so a session's note list spells what its chart showed; a key with no signature spells nothing on its own, the scale does), `tune-notation.ts` (tune → multi-system ABC + bar/chord-slot anchors), `chart-layout.ts` (density reflow, slash bars), `chord-layout.ts` (MuseScore-Jazz chord stacking), `ending-layout.ts` (volta placement — `[2]` opens a fresh system, glyphs repositioned never scaled), `chord-symbol.ts` (canonical chord model independent of the closed `ChordQuality` enum), `progression-display.ts` (per-progression identity hue, exhaustive Record so a new progression won't type-check without one). No side effects.
- **notation/** — DOM-adjacent but DOM-free chart plumbing, all Node-testable: `chart-geometry.ts` (hit rects from ABC char spans + reduced abcjs layout), `abcjs-adapter.ts` (adapts `visualObj` onto those shapes without importing abcjs types), `follow-scroll.ts` (teleprompter translateY math), `ending-align-dom.ts`.
- **matching/** — N-gram inverted-index melodic matcher shared by `/api/lick-match` (WJazzD attribution corpus) and client-side freestyle recognition (`book-index.ts` over the user's own licks only). `pitchWeight` defaults to 0.6; the attribution endpoint passes 0.7 explicitly.
- **audio/** — Everything touching Web Audio API: playback (Tone.js), capture (mic), pitch detection (Pitchy at 60fps), onset detection (custom AudioWorklet), note segmentation + quantizer (per-beat swing classification: swung eighths NOTATE straight — the beat vocabulary is {0, 1/3, 1/2, 2/3}, a beat is a triplet beat iff something lands near 1/3 or continues a quarter-note triplet from the right, and everything from straight 0.5 through `MAX_SWING` collapses to the straight off-beat eighth), bleed filter, metronome (click times are *computed* from tempo, not logged, so playback clicks suppress phantom onsets during segmentation; `METRONOME_TRIM` 0.6 sits under the volume knob so the knob is a mix position, not a raw gain; `scheduleMetronome` takes a `startAt` — pass TICKS, not `'2m'`, because bar notation converts through the sticky global `Transport.timeSignature`; `scheduleCountInClicks` is a distinct woodblock voice so the switch to the kit is the audible entrance cue in record-a-lick), backing-track rhythm section (bass/comp/drums — `backing-generation.ts` is the pure, seeded event engine: per-bar `GenerationContext` figures, walking-bass path planning with approach devices, rootless voice-led comping, spang-a-lang drums; all randomness via `generation-rng.ts` so replays are identical, swing applied at beat→tick conversion, drums are a `Tone.Part` not a `Sequence`), voicings, recorder + replay. Segmentation runs same-pitch consolidation, octave-boundary collapse, and whole-note octave-up-lock passes that merge artifacts only when no attack evidence exists, plus a **five-tier re-articulation splitter** (reading gap → clarity dip → envelope dip → HF spike → waveform `shapeBreak`). Two inverted rules there are load-bearing: `SHAPE_MIN_PERIODICITY` is a **floor, not a ceiling** (a legato tongue dips similarity *shallowly*; clicks and thumps dip it deeply), and the click-schedule veto is **conditional** on `bandRmsMin` (250–5000 Hz, a band no metronome voice reaches) because the beat is exactly where notes start. The HF tier's click suppression has three rescue shapes, one per tongue signature a click can't fake: the in-span band-floor dip, the pre-spike stop-and-recover (both `bandFloorDips`), and the feather tongue (`feathersTongueShape`, 2026-08-13 repeated-Eb pair) — no energy evidence at all, but a multi-frame `shapeBreak` dip in the shallow 0.80–0.92 band on a clean-baseline run, which also stands in for the fundamental-perturbation corroborator (measured clicks null shapeBreak or drive it ≤ 0.60; the corpus's shallow non-events are single-frame or ≥ 0.956). The reading-gap tier has its own click rule: a click can mask pitch tracking for a whole analyser window but can only ever ADD energy, so when a scheduled bleed event lands *inside* the hole the tier demands a genuine step-up (`RE_ARTICULATION_GAP_ATTACK_RISE`) rather than mere sustain — the plain sustain floor sits between a 0.67 decaying-note counterexample and real tongue stops at 0.94/0.97, and the 2026-08-10 pent run split a held G by landing at 0.85, right on it. The short-gap branch has a third acceptance path beside step-up and bloom — **broken entry** (`RE_ARTICULATION_BROKEN_ENTRY_SHAPE`, 2026-08-18 crescendo tongue): BOTH of the last two still-tracked frames before a true-silence hole carry `shapeBreak` ≤ 0.25 with energy sustained ≥ 0.85 across it. Depth's meaning is positional — in-span deep = click, but tongue damping is progressive so at the hole's entry it leaves TWO deep tracked frames where an impulse abrupt enough to blank tracking gets at most one (down-to-the-third's kick: −0.18 preceded by 0.99); the two-deep-frame Blue Monk thump is fenced off by the branch's silence gate instead (its hole is warmup-bridged). **The bleed evidence is load-bearing and is supplied by the caller.** `resolveOnsets` takes no bleed argument at all, so a click can and does survive as a base onset; what removes the resulting split is the `bleedOnsets` argument reaching `findReArticulations` and `mergeSamePitchWithoutAttack` (via `segmentNotes`). Dropping it at a call site silently restores the phantom — pinned in `pitch-replay.test.ts`, which scores the same take both ways.

  **Ear-training arms the capture before the user plays.** `capture-window.ts`. The pitch detector, onset worklet, MediaRecorder and transport snapshot all start when the listening window opens — a capture armed by its own first note can never hold that note's attack, because the trigger is a confident pitch reading and that needs most of a 4096-sample analyser window (~93 ms) of the note first. `trimToPerformance` then discards the reaction-time lead-in, keeping a fixed `PERFORMANCE_PREROLL_SECONDS` (0.35) ahead of the first confident reading. The pre-roll is bounded on BOTH sides: it must exceed the ~190 ms detection lag it undoes, and stay under the ~250 ms where DTW alignment starts to flip — `rhythmDistance` saturates at one beat, and re-scoring the fixture corpus shows 12 of 21 takes change grade between a 0.25 s and 0.5 s lead-in (always takes with a missed note, where rhythm is what decides WHICH note went missing). The trim is a pure function of the capture so the live path, the authoritative blob rescore and /diagnostics each re-derive the same offset instead of persisting one; `recordingTransportSeconds` keeps describing the blob's first sample and every consumer adds its own offset. Recordings captured before pre-arming have their first reading at ~0, so the trim is a no-op for them. Note lick-practice solves the same problem differently — one continuous detector for the whole session, windows sliced by `readingsStartCount` — because its windows open on a bar boundary, not on the user's entry. Record-a-lick (`/licks/record`) is the third variant: the entrance is SCHEDULED (bar-3 downbeat after a 2-bar woodblock count-in), so the detectors run from the top of the count-in and `rebaseToAnchor` re-origins the finished take on the anchor — the context time Tone hands the bar-3 `transport.schedule` callback (the audible downbeat, not the ~0.1 s-early callback time). No reaction time means no preroll; instead `ANCHOR_EARLY_TOLERANCE_SECONDS` (0.15 — above attack-transient scale, below one beat at 240 BPM so the last count-in click never survives) keeps slightly-early events at negative times and the quantizer clamps them to beat 0. The take then runs the SAME segmentation pipeline as ear-training (`resolveOnsets` + `findReArticulations` + `getMetronomeBleedOnsets` over the 8-beat transport offset — the click runs through the whole take, so dropping the bleed grid restores phantom splits), and review playback re-applies `settings.swing` because the notation is straight. The whole tail from raw capture to concert-C `Phrase` is `audio/record-transcription.ts` (`transcribeTake`, pure and Node-tested); the page owns only audio plumbing and UI state.
- **scoring/** — Pure functions: `score-pipeline.ts` (bleed filter + scoring orchestrator), `scorer.ts` (DTW + latency correction), per-note pitch/rhythm scorers, grades. No audio or UI dependencies.
- **phrases/** — Phrase generation, mutation, validation, library loading. Depends on music/ only. `transposeLickForTonality`: a MINOR cadence lick (`lickMode` minor, `PROGRESSION_CATEGORIES`) is keyed by its tonic and transposes tonic → tonality root under any tonality, never snapped — the parent-major hop assumes `lick.key` is the parent major, which sent a C-minor ii-V-i to F minor under a "D minor" daily tonality.
- **tunes/** — Tune domain logic: section flattening (`flatten.ts`, notation order vs `expandRepeats` playback order), book loading (`book-loader.ts`) with curated/user/adopted merge + whole-sheet transposition, `to-phrase.ts` bridge into the Phrase-consuming playback/backing engines, `segment-from-symbol.ts` (chord text → HarmonicSegment, shared by entry + importers), structural validation of foreign payloads, and the importers under `import/` (iReal Pro URL parser incl. the irealb:// unscrambler, Band-in-a-Box .SGU/.MGU binary + MusicXML fallback, MuseScore, Claude PDF-extraction JSON conversion). **PDF import timing is load-bearing**: one system-mode model call runs 15–345s on *identical* input (Fable's adaptive thinking, measured 2026-08-09), so `/api/tune-parse` answers on an NDJSON heartbeat (`Accept: application/x-ndjson`) — `proxy_read_timeout` measures the gap between reads, and the client's deadline is an INACTIVITY budget (`ndjson-result.ts`), never a total. `pdf-import-run.ts` fans every line out at once and keeps partial results: a line that fails all attempts is padded to empty bars by `assembleClaudeDoc` and flagged `untranscribed`, rather than discarding the lines that worked. The meter is **declared by the user before upload** (`TimeSignatureSelect`), because reading it off a transcription of line 1 serialised the whole import behind one call (263s of a 604s run) — text-layer SMuFL detection covers MuseScore exports only, so it can't replace the ask. Tunes store their real concert key (curated licks are stored in concert C — the TONIC, C minor for minor licks — and transposed at query time; user licks keep the concert key they were entered in, plus an optional `mode` resolved by `lickMode`); `HarmonicSegment.symbol` carries the raw chord text for display fidelity and `tune-notation.ts` in music/ renders chords/repeats/endings/multi-system ABC while leaving `phraseToAbc` untouched.
- **tricks/** — Parameterized melodic devices ("tricks": enclosures, triad pairs) practiced for *fluency*, not exact reproduction. `types/tricks.ts` holds the domain model: a `Trick` exposes `scoreConformance` (primary) and `generateExample` (secondary); progress is keyed by the composite `${trickId}:${normalizeParameterSignature(params)}` variant key, never by a generated preview phrase's id. `conformance.ts` clones the scoring DTW but swaps exact-pitch cost for formula-conformance tiers with partial credit (exact 1.0 / in-pattern 0.7 / in-scale 0.4 / out-of-scale 0.1 / missed 0); `example-generator.ts` realizes device slot specs to a validated `Phrase` (deliberately relaxed contour rules — triad pairs are leapy by design); `devices/` holds the two device modules + `index.ts` (fixed 2-entry `TRICKS`, no generic catalog); `mastery.ts` is the variant prerequisite graph (SCALE_PREREQUISITES pattern; unlock = 3 total passes of each prereq); the enclosures ladder is THREE parallel self-contained chains — one per chord type in `ENCLOSURE_TYPES` (major/minor/dominant, each with its own bed vamp and tune-alignment qualities; dominant excludes `7alt`, no natural 5th to target) — each the same 8 `ENCLOSURE_STEPS` with no cross-type gating, every chain's first rung unlocked from day one; the triad-pairs ladder is a strict linear chain over the 8 pair families pinned in `TRIAD_PAIR_FAMILIES` (diatonic → altered → whole-tone, each two (root-offset, quality) triads anchored to the chord root, disjoint pc sets, cell led by the lower-rooted triad). Enclosures build one of two figures off one parameter set via `TrickContext.figure`: the default FULL drill figure (a real anacrusis — pickup bar of approach notes, `pickupBars` stamped on the generated phrase — plus 4 content bars, each group resolving onto a downbeat) and the legacy 2-bar COMPACT gesture for tune-insertion windows, which are sized by the detected progression span and cannot fit the drill figure. `scoring/fluency.ts` combines conformance (0.7) with rhythm (0.3) into a **Score-compatible** result so grades/points/report paths work unchanged. Trick sessions ride the lick-practice single-lick round loop (`sessionType: 'trick'`, item `kind: 'trick'`, phrase regenerated each round, key rotation anchored at the player's **written C** in concert pitch (`trickEntryKey(instrument)` — concert Bb on tenor; the generation context stays concert C and transposes per key), bed vamp from the device's optional `practiceBed` — default `'major-vamp'`; altered/whole-tone families drill over `'dominant-vamp'`, the melodic-minor family over `'minor-vamp'`); tune practice emits suggestions per *selected* variant (`state/tricks.svelte.ts` SvelteSet), gated and aligned per family: a variant declaring `compatibleQualitiesFor` is matched to a full-bar progression chord of one of its qualities via `resolveQualityRoleEntry` and re-rooted on THAT chord (altered pairs land on the V of a long ii-V-I, substitutions bypassed), or skipped when nothing matches; scoring is via Fluency with played onsets rebased by the insertion alignment shift. Progress lives in `persistence/trick-practice-store.ts` (own storage keys; NEVER the lick store — composite keys must not enter lick blobs, guards exist in the report-reset and history-seed paths), synced as one `user_settings.trick_state` JSONB blob: selection is LWW by `selectedUpdatedAt` (union would resurrect un-starred variants), migrations union, per-(variant,key) progress by `lastPracticedAt`, tri-state cloud read (a failed read throws rather than merging against empty — the 2026-07-13 incident class). `persistence/trick-state-migrations.ts` holds pure blob rewrites (`enclosure-type-v1`: legacy no-`type` enclosure keys re-key to `type=major`); a migration runs once locally behind its marker AND on both sides of every cloud merge, because the merge unions variant keys and a stale row or old-code device would otherwise resurrect legacy keys forever.
- **difficulty/** — Adaptive difficulty: proficiency levels 1-100, 10 content tiers. The two scales overlap on 1-10, so `params.ts` exposes **two** lookups and no magnitude heuristic: `getProfileForTier(1-10)` (throws outside that range) and `getProfileForLevel(1-100)` (clamps, maps via `levelToContentTier`). Every production caller holds a *level*; only tier-walking tests use the tier form. The single overloaded `getProfile` they replaced inverted the bottom tenth of the 1-100 ear-training slider — a difficulty of 10 selected tier 10, "No Limits". `noteCountFloorLevel` returns a **level**, so it resolves through `getProfileForLevel`. Also `lick-phase.ts` — the four per-lick phases of expertise (new → learning → proficient → expert), a **display-only** derivation over a lick's progress series: `new` is key-coverage-driven (< 12 keys, whatever the tempo), the rest are tempo thresholds (120 / 150 BPM, reached = promoted). Nothing here gates practice, unlocks, or tempo; those rules stay in `state/lick-practice.svelte.ts`.
- **tonality/** — Daily key/scale selection, progressive unlocking.
- **state/** — Svelte 5 runes state modules (`.svelte.ts` files). Bridge between UI and logic.
- **persistence/** — localStorage wrapper + optional Supabase cloud sync.
- **components/** — Reusable Svelte UI components.
- **data/** — Curated lick catalog JSON files, rhythm pattern templates, progression templates.
- **step-entry/** — Manual lick entry helpers: duration metadata, pitch-input accidentals. The editor state carries `phraseMode` beside the WRITTEN `phraseKey`: typed naturals take the DRAWN signature (D minor gives Bb, not C#), the mode follows the chosen category until the user touches the Major|Minor control (`setCategory`/`setPhraseMode`), `switchToRelativeKey` relabels F major ↔ D minor without moving notes, and `getCurrentPhrase()` stamps `mode` on every saved lick. ### Key design decisions

**Concert pitch canonical.** All MIDI note numbers, scale data, and lick data use concert pitch internally. Transposition to written pitch (Bb/Eb instruments) happens only at display time in `phraseToAbc()` (notation.ts) and `concertToWritten()` (transposition.ts).

**Fraction-based rhythm.** Durations use `[numerator, denominator]` tuples (e.g., `[1, 8]` = eighth note, `[1, 12]` = triplet eighth). Conversion to seconds happens only at audio scheduling time.

**DTW scoring with latency correction.** Dynamic Time Warping in `alignment.ts` aligns expected vs detected note sequences. The scorer subtracts the median timing offset across matched pairs, absorbing constant human/detection latency.

**Local-first.** All writes go to localStorage/IndexedDB first. Supabase sync is optional and runs in the background. User data survives offline; page loads still need the network (no service worker — see tech-stack.md, "Installable web app").

**Shared AudioContext.** Tone.js and smplr share one AudioContext (via `audio-context.ts`) so Transport scheduling and sample playback stay on the same timeline.

### State management

State modules in `src/lib/state/` use Svelte 5 runes (`$state()`, `$derived()`, `$effect()`), not Svelte 4 stores. Key modules:
- **session.svelte.ts** — Single-phrase practice session (not persisted)
- **settings.svelte.ts** — User preferences (persisted to localStorage). Default swing is 0.62, not straight — deliberate: demos, the scoring grid and record-a-lick review playback all follow the knob, and exactly 0.50 doubles as `resolveBackingSwing`'s "band follows the tempo curve" sentinel, so the shipped default pins the band to the knob and dialing back to 0.50 restores the tempo curve. `metronomeVolume` (default 0.5) is a mix position — `METRONOME_TRIM` applies underneath in audio/metronome.ts.
- **progress.svelte.ts** — Session history + adaptive state (persisted, bounded to 100 entries)
- **history.svelte.ts** — Long-term daily progress summaries for calendar heatmaps and period comparisons (persisted, survives the 100-session prune window). **Derive-on-write**: summaries are a pure derivation of two source-of-truth tables (`progress.sessions` and `lick-practice-sessions`); every write to either source calls `recomputeDailySummary(date)` so divergence is impossible and replaying a write is a no-op.
- **licks.svelte.ts** — Search state for the Licks page (not persisted, exports the `licks` rune). The /licks route is now focused on the user's *own* book — three derived sections (`needsSetup`, `practiceSet`, `otherLicks`) over user + adopted-community licks; the curated ear-training catalog isn't surfaced here. Category/difficulty browse filters were retired with the refocus; the remaining filters are search and a progression filter (`licks.progressionFilter`), which narrows to licks carrying the matching explicit `prog:*` tag via `getProgressionTags`.
- **lick-practice.svelte.ts** — Multi-key lick-practice flow: progression plans, per-key results, tempo adjustments, gradual key unlocking. Advancement gates: `KEY_PROFICIENT_THRESHOLD = 0.90` (green tier — counts toward unlocks and tempo bumps), `KEY_FLOOR_THRESHOLD = 0.75` (a single key below this blocks tempo *increases* and unlocks; decreases still apply), yellow band 0.75–0.89 (passable but doesn't earn). Tempo moves once per lick per session by `computeAutoTempoAdjustment(avg)`: +2 at ≥ 0.95, +1 at ≥ 0.90, −1 at ≥ 0.75, −3 below — except on an unlock session, which skips the delta and drops the tempo 10% instead (`tempoAfterKeyUnlock`, rounded, clamped at MIN_TEMPO): the gate only opens on strong sessions, so the new key would otherwise arrive faster than the tempo that earned it. Each unlock requires avg session score ≥ 0.90 AND newest-key `passCount` ≥ `UNLOCK_PASSES_REQUIRED` (3) AND no floor failure; keys appear in alternating sharp/flat-side neighbours of the entry key on the circle of fifths. Three start paths share the engine: **standard sessions** pin to one progression; **Daily Practice** (`startDailyPracticeSession` / `buildDailyPracticePlan`) rotates across every progression the user has `prog:*` tags for, picks each lick's least-recently-practiced compatible progression via `pickProgressionForLick`, and the post-session writer splits the report by progression so the least-recently-practiced lookup stays correct across mixed sessions; **single-lick Deep Practice** (`startSingleLickSession`, launched from the Practice button on a lick's detail page) drills one lick through its currently-unlocked keys only and **derives its progression from the lick's own `prog:*` tags** rather than `config.progressionType` — fixes the major-lick-over-minor-vamp bug — and refills the rotation when every unlocked key clears ≥ 0.95. **Deep practice runs its own tempo rule, entirely in session state** (`lick-practice-rotation.ts`): it opens at `deepPracticeStartTempo` (2% under the lick's stored tempo, `Math.min(t - 1, …)` so rounding can't make the ease-in a no-op) and bumps by `nextCycleTempo` — `config.tempoBumpPercent` (default 1) of the *current* tempo, rounded UP because 1% below 100 BPM would otherwise floor to zero. Nothing on that path persists: `recordKeyAttempt` writes the lick's **baseline** (`prev?.currentTempo ?? resolveLickTempo`) rather than `lickPractice.currentTempo` when `mode === 'single-lick'` — it can't just omit the field, since `updateKeyProgress` merges over `getKeyProgress`'s 100-BPM default — and the lick branch of `advanceSingleLickRound` writes neither per-key tempo nor an `appendLickProgressPoint` sample (a history point at an unheld BPM would promote the lick across `lick-phase.ts`'s display thresholds while Daily still runs it slower). The trick branch deliberately still persists: clearing the rotation IS the trick unlock, and tricks have no daily-session return path. The discount is applied at the `startSingleLickSession` call site, never inside `resolveLickTempo`, which every session type shares. **The report's weak-key recommendation launches the focus ramp** (`startSingleLickSession(lick, { focusKey })` → `lickPractice.ramp`; pure policy `planFocusRamp`/`resolveRampCycle` in `lick-practice-rotation.ts`): that key ALONE at `focusStartTempo` (10% under — the unlock dip) on a staircase — clear → `nextCycleTempo`, sub-floor → `focusStepDownTempo` (3× the bump), else hold — until a clear lands back at the saved tempo, then the other unlocked keys re-admitted one per cleared rotation, worst first, tempo held, until the full set is back; only then does clear-bump-refill resume. Report-CTA-only (the detail page and setup still start on the full worst-first circle), session-local like the rest, `sessionKeys` stays the full circle, and `LickHeader`'s "Key n/N" slot shows the phase. An omitted `tempoBumpPercent` now falls back to the config knob instead of resetting it to 1%. Deep-practice cycles are **continuous**: no rest bars and no per-round card — the last key's close event runs the cycle boundary synchronously (advance → worst-first re-sort → schedule next cycle one bar out) and a 1-bar full-rhythm-section ii-V turnaround (`audio/turnaround-bar.ts` + `playBackingHitsNow`, standalone transport events because `scheduleNextPhrase`'s deferred `disposeBackingParts` would kill Part-scheduled tail audio) joins the cycles, targeting the next head key. The rotation is sorted worst-first by per-key `rollingScore` (EWMA over EVERY attempt, persisted in `LickPracticeKeyProgress`, updated by `recordKeyAttempt` which now writes on failures too — always with explicit `currentTempo`, else the store's 100-BPM default would leak into fresh licks) so the demo lands on the struggling key and the user answers in it immediately; the demo is **skipped** once the head key's rolling score ≥ 0.90 (`demoNextCycle`, `getDemoBars` — the single source for super-phrase layout AND window scheduling; standard sessions always demo, first cycle of a session always demos; tricks demo only on a round whose example STYLE is new to the session — `trickRoundIntroducesStyle` in tricks/index.ts — so enclosures demo once and triad pairs once per style, because a regenerated realization of the same figure is not new to the ear). Pure cycle policy lives in `state/lick-practice-rotation.ts`. In-flow feedback: a transient per-key score flash on the chart row plus session-long ring state (`latestKeyResults`/`sessionKeys` — the ring needs a stable key set because the rotation shrinks and reorders). Licks need an explicit `prog:<progressionType>` tag to be eligible; tags seed automatically on category writes (`updateLickCategory`) — for the templates the lick's OWN harmony fits (`progressionFitsLick` in `data/progressions.ts`: a 1|1|1-bar ii-V-i fits the long template only, never the half-bar short one, never a vamp; harmony-less editor licks need a native entry long enough; chord-quality licks need their chord family in the slot; everything else honours the tag) — and are not auto-inferred on hydrate, so user-removed tags stay removed. The same rule greys the detail-page pills with a reason (a tagged-but-unfit pill stays removable), filters `pickProgressionForLick`/`getPracticeLicks` at read time, and `pruneIncompatibleProgressionTags` drops misfits on every successful hydrate inside the `cloudOk` gate. The minor templates are ii-7b5 · V7b9 (phrygian-dominant) · i-7 via `MINOR_CADENCE`, shared with the turnaround cue and `getTransitionCadenceChords`; the session chart prints the V stacked MuseScore-Jazz style (`chordChartSymbol`). `buildPhraseFor` stamps `mode: progressionMode(type)` so a minor drill labels its keys `Dm` (`keyLabel`) everywhere — header, rows, ring, report, progress page. The one-time category-inference migration (`backfillInferredProgressionTags`, run via `runLickMetadataMaintenance`) was **removed** in the data-layer simplification (PR #165) along with the orphan reconciler — don't reintroduce inference-on-hydrate. `backfillPracticeTags` does still run on each hydrate, but only to migrate *legacy* `practice` markers out of `lick.tags`/tag overrides, and it is gated on the cloud hydration reporting success (writing over a store that failed to hydrate would push a partial blob over the intact cloud row — the 2026-07-13 incident class). The reserved `__migrations` tag key survives in `persistence/lick-metadata-merge.ts`, where it is always unioned rather than last-writer-wins, so any legacy `prog-backfill-v1` marker is preserved rather than dropped by a merge. Per-lick reset (`resetLick`, backed by `resetLickPersistence` in the store) clears scores + unlock count for one lick (tags preserved) and is surfaced from both the post-session report (for try-again-band licks) and the book detail page. Progress persisted via `persistence/lick-practice-store.ts`.
- **tricks.svelte.ts** — Trick-practice *selection* only (`trickState.selectedVariants`, a `SvelteSet` of composite variant keys so `.add()`/`.delete()` stay reactive); per-variant progress lives in `persistence/trick-practice-store.ts`, not here. Mutations save locally then enqueue an outbox push. `hydrateTrickStateFromCloud` delegates the pull-merge to `initTrickStateFromCloud` and then **re-seeds** the set from the merged local store rather than unioning with the live set (selection is LWW; a union would resurrect variants deselected on another device), skips `persistSelection` on that path so hydration can't stamp a fresh mtime and fake "newest", and bails on a scope-generation change so a mid-flight user switch can't write the previous user's state. (Persisted via the store.)
- **tune-entry.svelte.ts** — Long-form tune entry built ON TOP of the shared `stepEntry` buffer: the section list is authoritative and melody is edited one ≤4-bar PAGE at a time through step-entry (so `PitchEntryPanel`/`DurationSelector`/keyboard entry work unmodified); the buffer commits on page/section navigation and is suspended (committed + emptied) on route exit so `/licks/editor` never sees tune content. Exports the `tuneEntry` rune plus `initNewTune`/`resetTuneEntry`, `loadFromTune`, and `buildDraftTune`. Chords are typed as written-pitch text (`parseChordSymbol`), stored concert with re-derived change-point durations. Manual entry is 4/4-only (`melodyEditingSupported`); imported charts in other meters keep their meter with melody editing gated off so the 4/4 buffer can't corrupt them. `loadDraftForReview` hydrates an unsaved import draft in create mode; the PDF flow uses `loadFromTune` with a pre-assigned id so the stored PDF stays linked. (Not persisted.)
- **tune-community.svelte.ts** — Filter state for the tune community browse page (not persisted, exports `tuneCommunity`).
- **tune-practice.svelte.ts** + **tune-practice-plan.ts** — Scored tune-practice sessions, split the same way lick-practice is (thin runes wrapper over a plain, Node-testable logic module; the route owns audio orchestration). The plan module holds `buildSessionPlan` (detected progressions → `InsertionPoint[]` carrying BOTH timelines plus transport ticks), `headBarsForFlat` (the jazz form rule — decided from the EXPANDED section map, never raw repeat markers, which imports express inconsistently; an internal repeat like `|: A :| B A` is *not* a form outline), `buildSessionPhrase`, `assignSuggestRotation` (least-used-first, because per-point suggestion lists differ in order and length so an index-modulo starves licks), `strictnessKnobs` (maps onto EXISTING pipeline knobs only — the grading scale never changes), `applyInsertionResult` (points = `round(overall*100)`, doubled when this and the previous window both clear `KEY_PROFICIENT_THRESHOLD`), and `indexResultsByInsertion` (keyed, not positional — a skipped window contributes no result and would misalign everything after it). Consumers must read `TunePracticeAudioPlan.playHead` (the effective `config.playHead && hasMelody`), not `config.playHead`. **Results are deliberately not persisted** — no streak, no adaptive movement, no per-key lick writes. (Not persisted.)
- **tour.svelte.ts** — Guided-tour completion/dismissal (persisted + cloud-synced; cloud wins for completion so a finished tour never replays on another device). `resetTours` bypasses `saveTourState` because that path UNIONS with the remote row — a cleared set would be re-added.
- **step-entry.svelte.ts** — Manual lick entry UI state: current duration, octave, accidental, entered notes, plus `editingId`/`editingSource`/`editingTags`/`editingCategory` when re-opening an existing user-entered lick. `selectedNoteIndex` tracks a user-selected element — note OR rest (set by clicking a notehead/rest glyph or `selectPrev`/`selectNext` on ←/→, which stop on rests, MuseScore-style); the selection is the target of `deleteSelectedNote` (any element; nothing selected → last element of any kind) and of `adjustSelectedNotePitch`/`flipSelectedNoteSpelling` (pitched only: a selected rest is a hard no-op — never a silent retarget; nothing selected → last pitched note). `deleteLastNote`/`adjustLastNotePitch`/`flipLastNoteSpelling` remain as aliases. Mid-list deletes shift later offsets and repair straddling ties. `loadFromPhrase(lick)` hydrates the state for edit mode; `/licks/editor` branches on `editingId` to switch button labels, skip duplicate self-match, and redirect to `/licks/<id>` after Update. (Not persisted.)

## OMR subsystem (`omr/` — Python, standalone) + hybrid PDF import

**Hybrid import (2026-08-10)**: `/tunes/import/pdf` accepts an optional `.omr.json` (from `python -m omr transcribe`) attached before the PDF. `src/lib/tunes/import/omr-transcription.ts` validates it as untrusted input (adopted-validator pattern), slices the flat OMR measure list into per-system chunks by geometry bar counts, and converts whole-note `[num,den]` fractions to declared-meter-denominator beats — feeding the SAME `ModelBar` seam Claude fills, so `assembleClaudeDoc`/`claudeJsonToTune` are untouched. Covered systems never call `/api/tune-parse`; uncovered ones fall back to Claude (or stay blank keyless — OMR import works with no AI key). Comparison pinned in `pdf-vs-musescore.test.ts`'s OMR family: melody 0.89–1.0 vs Claude's 0.5–0.6 floors, chords exact-position on 2/3 charts, A-Train form strict. Fixtures re-record via `RECORD_OMR_FIXTURES=1 npx playwright test record-omr-fixtures --project=chromium` (committed recorder, env-gated so CI never rewrites fixtures).

A uv-managed Python 3.12 project (own `pyproject.toml`/`uv.lock`/`.venv`) that transcribes lead-sheet PDFs/images to symbolic notation — the future replacement for direct vision-LLM reading in PDF import. **Nothing in the app calls it yet**; `/api/tune-parse` is untouched. Docs: `docs/omr/README.md` + `docs/omr/legato2.md`. Key invariants: everything depends on the `OMRBackend` protocol (`backends/base.py`), never a concrete engine; raw model output is preserved verbatim and never "fixed"; the normalizer records only what was recognized (absent = `None`, chords kept as raw text, Db never respelled to C#); validation flags, never rewrites. **LEGATO 2 is unreleased** (paper-only as of 2026-08-09) — `Legato2Backend` is a documented stub, and `LegatoV1Backend` (vendored MIT code in `vendor/legato/`, pinned checkpoint) is experimentation-only: it transcribes NO text, so **chord symbols are absent by design** (standing `TEXT_ELIDED_BY_MODEL` warning; benchmark chord metrics ≈ 0). Unit tests are hermetic (no downloads); model tests are behind `pytest -m omr_integration` and need HF auth for **two** gated repos — the checkpoint AND `meta-llama/Llama-3.2-11B-Vision` (the 429MB checkpoint is decoder-only; the frozen encoder streams from Meta's repo at load time). CI runs the hermetic suite via the path-filtered `omr-changed` parameter, mirroring `nginx-changed`. The 961MB droplet can never run inference — local/dev only. Ground-truth files under `omr/tests/benchmark/ground_truth/` are written-pitch-as-printed; converted ones stay `"reviewed": false` until checked against the printed page.

## Code conventions

- **Svelte 5 runes only** — no `$:` reactive statements, no Svelte 4 stores
- **TypeScript strict mode** — explicit types for parameters and returns
- **File naming**: kebab-case for `.ts` files, PascalCase for `.svelte` components, `.svelte.ts` for state modules
- **Commit style**: Conventional Commits (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`)
- **Scoring weights**: pitch accuracy 60%, rhythm accuracy 40%
