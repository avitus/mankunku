**Browser automation must stay off the user's desktop.** Use `npm run test:e2e`
(or `test:e2e:ui` for a manually opened web inspector). The runner snapshots this
worktree into a disposable Linux Docker container, backed by a headless VM on
macOS. Direct host Playwright runs are blocked. Never bypass the boundary or
launch ad-hoc host browsers for automated verification. Missing Docker means
set up the engine, not fall back locally. See `tests/e2e/README.md` for Colima
setup, limits, reports, and Linux Firefox audio coverage limitations. Node-only
unit tests remain safe locally; `npm run test:sandbox -- unit` also isolates them.

`svelte.config.js` wraps adapter-node in `withoutEmptyChunkWarnings` (`scripts/quiet-empty-chunks.js`, tested in `tests/unit/build/`). The "Generated an empty chunk" lines were never Vite's: adapter-node re-bundles the server output with Rollup, keeps every Vite server file as its own chunk, and Rollup warns for each browser-only module it tree-shook to nothing (wake lock, IndexedDB recordings, SvelteKit's own env stub). True and unactionable, and the adapter takes no Rollup options — so that ONE message is dropped for the adapter step only. Don't "fix" one by restructuring app imports.

CI pipeline (CircleCI): `test` and `e2e` run in parallel on every branch, each after its `list-*-tests` job; on `main` only, `build` follows `test`, `db-migrate` follows `build`, and `deploy` waits for `build`, `db-migrate` AND `e2e` (the path-filtered `omr-test` and `nginx-deploy` pipelines run beside it). Deploy rsyncs to a Digital Ocean server and restarts via PM2; db-migrate runs `supabase link` + `supabase db push --linked` against the production database, authenticated via the `SUPABASE_ACCESS_TOKEN` env var (no DB password needed). The deploy target is the CircleCI project environment variable `DEPLOY_HOST`, managed in the CircleCI project settings and nowhere in this repo — a server move is finished only once it is updated there. Incident context, not configuration: production moved to a new 4GB droplet on 2026-09-08 (64.23.176.115 at the time of writing), and PR #247's merge deploy landed on the retired droplet until the job's public verify step caught it.

Tests run through **CircleCI Smarter Testing** (`.circleci/test-suites.yml`: suites `unit tests`, `e2e tests`, `omr tests`, one atom per test FILE; `circleci testsuite doctor "<suite>"` validates one). Every credit-charged feature has been on since 2026-10-20, at Andy's request, while CI times are measured:
- **Test impact analysis.** On branches only the files a change reaches run. The impact data is refreshed on main by the non-blocking `unit-analysis` and `e2e-analysis` jobs; omr analyses inline. Unit analysis collects V8 coverage after every test, single-threaded (12.5 min locally for the full suite), which is why it is off the deploy path.
- **Dynamic parallelism.** `list-unit-tests` and `list-e2e-tests` size `test` and `e2e` through the experimental stanza at the bottom of continue-config.
- **Dynamic test splitting** and **auto-rerun** of failed atoms.

Three non-obvious shapes:
- Unit discovery is `find`, not `vitest list`, whose output failed to parse on CircleCI.
- E2E atoms are testDir-relative (`smoke.spec.ts`), because Playwright's JUnit names files that way; `run` restores the prefix, since a bare `smoke.spec.ts` regex also matches stub-cloud-smoke.
- E2E builds once per node, because dynamic splitting runs Playwright once per batch. Impact data for e2e is the app chunks each test's Chromium context REQUESTED, mapped to sources BY CHUNK (`tests/e2e/fixtures/circleci-coverage.ts` + `app-chunks.ts` + its reporter, over an `E2E_SOURCEMAPS=1` build), so server-only paths are listed as full-run paths. Never `page.coverage`: Playwright's `startJSCoverage` always starts V8's precise block coverage, which ran the PDF-import tests 2–2.5× slower and timed them out on the 2-vCPU analysis box (every main workflow red, 2026-10-21); the request set yields the identical map.

The local runs `doctor` makes leave `.circleci/impact-*.json` and `.circleci/state-*/` behind, both gitignored.

`deploy/app/release.sh` runs **on the server** and is covered by `npm run test:deploy` (`deploy/app/release.test.sh`, wired into the `test` job — it stubs npm/pm2/curl onto PATH, so it runs anywhere; the deploy-lock tests need `flock` and skip on macOS). Four invariants it exists to protect, all learned from incidents:
- **Dependencies are shared, not per-release.** `npm ci` peaks near 500MB installing 378MB/22k files on the 961MB droplet of the time (4GB since the 2026-09-08 move; the sharing stays, most deploys ship code, not dependencies) — it was OOM-killed on 2026-08-07/08 while the lockfile was byte-identical across all three deploys. Deps now install once into `shared/deps` and symlink into each release, keyed on **both** the lockfile and the Node version (`.installed-package-lock.json` + `.installed-node-version`, written only after a successful install so a killed one can't look satisfied). Node is part of the key because native bindings compile against an ABI the lockfile says nothing about — without it, a Node upgrade would silently reuse a tree built for the old runtime. Tradeoff: rolling `current` back gives that release the newer deps.
- **A failed deploy removes its own staged release** — unless `current` already points at it, in which case that dir *is* production and deleting it would turn a failed deploy into an outage. Cleanup unlinks `node_modules`, never follows it into `shared/deps`.
- **`pm2 start` returning 0 is not a deploy.** It only means the process spawned. release.sh polls `/api/health` and compares the **release id**, since a stale process still holding the port answers 200 happily; the deploy job then re-checks the public URL for the commit SHA.
- The droplet has **2GB swap** (added 2026-08-08; the 2026-09-08 clone kept it) because the box has no headroom for burst allocations.

### Database migrations

Create new migrations with `npx supabase migration new <name>`, which produces the Supabase-standard `<YYYYMMDDHHMMSS>_<name>.sql` UTC-timestamp filename. **Do not hand-number new migrations.** Migrations `00001`–`00023` use a legacy sequential scheme; the Supabase dashboard derives its "inserted at (UTC)" column by parsing the version string as a timestamp, so those legacy ones render "Unknown" forever. Renaming them retroactively would require rewriting the `version` primary keys in production's `supabase_migrations.schema_migrations` in lockstep — if files and table rows disagree, the CLI treats every migration as pending and CI's db-migrate job fails. So the legacy names stay; only new ones get real dates. Mixed schemes order correctly, since `00023` sorts before any `2026…` string.

`user_licks.mode` (TEXT NULL, 'major'|'minor'; NULL = not stated) rides FOUR hand-written mappers — `user-licks.ts` `cloudRowToPhrase`/`phraseToRow`, `community.ts` `rowToPhrase`, `sync.ts` `toRow` — and the reconcile is whole-row LWW, so a mapper that forgets the column writes NULL and erases the mode on the next pull (each mapper has a test). `src/lib/supabase/types.ts` is **hand-maintained**, not generator output — edit it by hand when a migration changes the schema, then run `npm run db:types:check` (needs the local stack) to verify it matches the database. There is deliberately no regenerate-in-place script: generating over it drops the source-interface mapping in its header, adds the unused `graphql_public` schema, and widens `public_lick_authors.id` to `string | null`, which would widen the Map key type at three call sites in `persistence/community.ts` for a NOT NULL primary key.

The CLI is linked to the **production** project ref. Local commands need an explicit `--local` (`npx supabase migration up --local`); the `--linked` variants target production. `npm run db:reset` defaults to local but rebuilds from scratch, so prefer `migration up --local` to apply pending migrations in place.

## Architecture

Mankunku is a jazz ear training PWA. It plays a phrase, the user plays it back on their instrument via microphone, and it scores pitch/rhythm accuracy in real time. Built with SvelteKit 2, Svelte 5 (runes), TypeScript strict mode, Tailwind CSS 4, Tone.js, and Pitchy.

### Core module boundaries (`src/lib/`)

- **types/** — Pure TypeScript interfaces grouped by domain. No runtime code.
- **music/** — Pure functions for music theory (scales, intervals, keys, transposition, chords) and engraving policy: `notation.ts` (phrase → ABC with the minor key table — `signatureAccidentalsFor`/`keyLabel`/`abcKeyField`: a minor lick is keyed by its TONIC + `Phrase.mode`, drawn with the relative major's signature (six flats for Eb minor, labelled Eb-; Ab/Db minor label G#-/C#-), `K:Dm`; `mode.ts` owns `lickMode` = explicit `mode` › harmony's tonic segment › major, NEVER the category, because legacy user licks in minor categories were entered with key = relative major; also the ONE enharmonic policy — `spellingContextAt` + `resolveUseFlats`: explicit › key signature › the segment's declared scale, which settles only the chord tier's three ambiguous degrees b3/#9, b5/#11, #5/b13 › governing chord (whose ninth semitone over a dim7 is the seventh: E°7's Db, not C#; a Cbb takes the sixth's letter, Bb) › key default — shared by the lick chart and every note-name display so a session's note list spells what its chart showed; a key with no signature spells nothing on its own, the scale does. Tune charts and the lick-practice lead-sheet row (both engraved by `tuneToAbc`) call the same chain since 2026-09-11 — they used to run an inline copy without the scale tier, and the row disagreed with the lick chart on ~13% of curated-lick renders; DISPLAY-ONLY — `formatChordSymbol`/ABC text stay canonical ASCII-plus-Δ; drawn in `--chord-font` (Fraunces + Edwin supplying Δ ♭ ♯, app.css) by NotationDisplay's SVG tspans and the HTML chart/`ChordSymbolText`; its TEXT entry (`chordDisplayModelFromText`, no key) keeps the root and bass letters the text wrote via `chordSymbolSpellings` — the chart already spelled them for its key, and the canonical `ChordSymbol` root is a `PitchClass` (Ab for G#, only F# sharp-canonical), so rebuilding from it drew Autumn Leaves' G#-7b5 · C#7b9 on tenor as A♭ø7 · D♭7(♭9) under three sharps beside a correct F♯- (2026-09-17, on every surface: tune charts, the lead-sheet row, ChordChart, chord lists)), `ending-layout.ts` (volta placement — `[2]` opens a fresh system, glyphs repositioned never scaled while line art scales: the volta onto `[1]`'s span, every beam, tie, slur and triplet bracket by `endingLineArtTransform`, which carries each end with the note it rests on — abcjs draws a beam as `path.abcjs-beam-elem` with no group, so until 2026-10-25 a stacked `[2]`'s beams never moved; the pass assumes the `[2]`'s system was drawn full width, true of every system but the last, so a stacked `[2]` that ENDS the tune emits `%%stretchlast 1` (Mankunku Blues' staff stopped two bars in), and every stacked `[2]` opens on `|[2`, a barline the pass moves under `[1]`'s; a section whose first bar is a partial pickup fills one column fewer, a pickup-only section fills none and leaves its system open for the section after it), `pickup.ts` (the ONE resolver for a tune's anacrusis — `resolvePickupLength`: the explicit `TuneSection.pickupLength` when the melody agrees, else ONLY for the legacy import shape (first section, blank label, one bar, a form after it — a lone blank section is a lick's lead-sheet window, never a pickup) the length inferred from the first pitched beat, so pre-field imports render right with no re-import; the timeline keeps a FULL bar and only the engraving is short: `tune-notation.ts` gap-fills from the silent prefix (stored rests in it dropped, a straddler clipped), shortens `chordBar`'s spacers to match, breaks lines with the partial bar in no column, emits `[I:setbarnb 1]` after its barline because abcjs counts an anacrusis as bar 1, closes a pickup-only section with a thin `|` — or lets the next section's `|:` be its barline — and hands the pickup line the boxed letter of the section it leads into since abcjs draws part labels only at a line start; No side effects.
- **notation/** — DOM-adjacent but DOM-free chart plumbing, all Node-testable: `chart-geometry.ts` (hit rects from ABC char spans + reduced abcjs layout), `abcjs-adapter.ts` (adapts `visualObj` onto those shapes without importing abcjs types; chords stay on their beat — `chordSymbolDeltas` lifts each over the ink beneath it and `chordHorizontalNudges` moves one only off ink overlapping its DRAWN box, which `NotationDisplay` measures with the drop applied: a band reaching below the box shoved the chords over a bar of high beamed eighths to the barline, 2026-10-25; `alignSystemLayouts` maps a stacked `[2]` system's items through the transform `ending-align-dom.ts` returns, because every x-span — bar zones, beat cells, range markers, the playhead, the editor's hit rects — is derived from abcjs's PRE-alignment layout and used to draw at the line start while the glyphs sat under `[1]`; the bands stay unremapped since they carry only y, measured after the pass), `follow-scroll.ts` (teleprompter translateY math), `ending-align-dom.ts`, `abcjs-loader.ts` (the ONE dynamic import of abcjs — ~500 KB raw / ~125 KB brotli, the second-largest chunk: a memoised `load()` every consumer shares plus a synchronous `loaded()`; `NotationDisplay` reads from it and the lick-practice session route calls `load()` at mount, alongside the mic/sample/detector setup, because the first lead-sheet row used to issue the fetch from its own mount = the moment the count-in starts; a failed fetch is retried, never cached).
- **matching/** — N-gram inverted-index melodic matcher shared by `/api/lick-match` (WJazzD attribution corpus) and client-side freestyle recognition (`book-index.ts` over the user's own licks only). `pitchWeight` defaults to 0.6; the attribution endpoint passes 0.7 explicitly.
- **audio/** — Everything touching Web Audio API. **Each transport tick is delivered once** (`tick-redelivery.ts`, 2026-10-01): Tone's clock can hand one tick to two consecutive passes when a pass ends exactly on it, and every non-once event on that tick then fires twice — the melody Part (a doubled smplr attack, +6 dB), non-looping backing Parts, the finite metronome/count-in Sequences (a synth throw), record-a-lick's entrance `transport.schedule` (a second `beginActiveRecording` orphans the 2 s silence timer, which then cuts the take). `scheduleOnce`, `scheduleRepeat` and looping Parts were never affected: each occurrence is a once-event that removes itself. `initAudio` wraps `transport._clock.callback` (Tone-private; the real-Tone tests in `tick-redelivery.test.ts` pin the shape) and drops a tick that repeats the previous tick's NUMBER within 1 ms. Both halves are needed: tick numbers restart after a stop, and a time-only key drops a real downbeat — a `stop()`+`start()` at `now()` right after a pass that ended on a tick puts tick 0 at that very instant. The price is a transport LOOP, whose wrap renumbers a re-delivered tick to loopStart; the app never loops the transport, and the gap is an `it.fails` pin. Playback (Tone.js — cancellation is ONE boundary, in `playback.ts`: `playPhrase`/`scheduleNextPhrase` claim a generation token before their first await and `stopPlayback()` bumps it synchronously, so a route's `onDestroy` cancels a `playPhrase` still mid-setup with no per-route guard — no route awaits its play handler at teardown, whether the handler itself awaits `playPhrase` or `void`s it as lick-practice's `startLick` does; the token reaches the helpers as `isStillCurrent` (`scheduleMetronome`, `scheduleBackingTrack`), which allocate nothing once it is false and do not touch the slot whichever way it flipped, since after a newer phrase the slot is that phrase's; `playback-cancellation.test.ts` holds the Tone lookup and activation, `playback-cancel.test.ts` the helpers), capture (mic), pitch detection (Pitchy at 60fps), onset detection (custom AudioWorklet), note segmentation + quantizer (per-beat swing classification: swung eighths NOTATE straight — the beat vocabulary is {0, 1/3, 1/2, 2/3}, a beat is a triplet beat iff something lands near 1/3 or continues a quarter-note triplet from the right, and everything from straight 0.5 through `MAX_SWING` collapses to the straight off-beat eighth), bleed filter, metronome (click times are *computed* from tempo, not logged, so playback clicks suppress phantom onsets during segmentation; `METRONOME_TRIM` 0.6 sits under the volume knob so the knob is a mix position, not a raw gain; `scheduleMetronome` takes a `startAt` — pass TICKS, not `'2m'`, because bar notation converts through the sticky global `Transport.timeSignature`; `scheduleCountInClicks` is a distinct woodblock voice so the switch to the kit is the audible entrance cue in record-a-lick; every Sequence callback also goes through `playEachBeatOnce`, the inner layer under the transport guard and kept because the metronome is where a duplicate fails hardest: a synth restarted at one instant throws "Start time must be strictly greater than previous start time", which became reachable once practice went metronome-only by default, 2026-10-01), backing-track rhythm section (bass/comp/drums — `backing-generation.ts` is the pure, seeded event engine: per-bar `GenerationContext` figures, walking-bass path planning with approach devices, rootless voice-led comping, spang-a-lang drums; all randomness via `generation-rng.ts` so replays are identical, swing applied at beat→tick conversion, drums are a `Tone.Part` not a `Sequence`), voicings, recorder + replay. Segmentation runs same-pitch consolidation, octave-boundary collapse, and whole-note octave-up-lock passes that merge artifacts only when no attack evidence exists, plus a **six-tier re-articulation splitter** (in execution order: reading gap → HF spike → envelope dip → clarity dip → waveform `shapeBreak` → timbre switch; onsets are merged, sorted and deduped afterwards, and the clarity tier defers to a hole the gap tier already marked). Two inverted rules there are load-bearing: `SHAPE_MIN_PERIODICITY` is a **floor, not a ceiling** (a legato tongue dips similarity *shallowly*; clicks and thumps dip it deeply), and the click-schedule veto is **conditional** on `bandRmsMin` (250–5000 Hz, a band no metronome voice reaches) because the beat is exactly where notes start. The HF tier's click suppression has three rescue shapes, one per tongue signature a click can't fake: the in-span band-floor dip, the pre-spike stop-and-recover (both `bandFloorDips`), and the feather tongue (`feathersTongueShape`, 2026-08-13 repeated-Eb pair) — no energy evidence at all, but a multi-frame `shapeBreak` dip in the shallow 0.80–0.92 band on a clean-baseline run, which also stands in for the fundamental-perturbation corroborator (measured clicks null shapeBreak or drive it ≤ 0.60; the corpus's shallow non-events are single-frame or ≥ 0.956). The envelope-dip tier needs a corroborator to tell a tongue from a breath pulse. It accepts tongue noise (hfRms ≥ 2× the run), a fundamental wobble (≥ 0.08 st), or, since 2026-09-18, a **reed reset** (`resetsReed`): a SHALLOW shapeBreak dip inside the envelope dip, judged by the shape tier's own gates (clean baseline, ≥ `SHAPE_MIN_DROP`, not under `SHAPE_MIN_PERIODICITY`). The blues-curl-up Db tongue missed both older gates (1.86×, 0.057 st) and read 0.958 at the bottom of its dip. The shape tier refuses that break on purpose, because its `SHAPE_MIN_SUSTAIN` gate rejects any break whose energy dips, so each tier held half the evidence. A deep break (0.842, sharp-9's D re-blooming after its ghost hole) stays refused. The reading-gap tier has its own click rule: a click can mask pitch tracking for a whole analyser window but can only ever ADD energy, so when a scheduled bleed event lands *inside* the hole the tier demands a genuine step-up (`RE_ARTICULATION_GAP_ATTACK_RISE`) rather than mere sustain — the plain sustain floor sits between a 0.67 decaying-note counterexample and real tongue stops at 0.94/0.97, and the 2026-08-10 pent run split a held G by landing at 0.85, right on it. The short-gap branch has a third acceptance path beside step-up and bloom — **broken entry** (`RE_ARTICULATION_BROKEN_ENTRY_SHAPE`, 2026-08-18 crescendo tongue): BOTH of the last two still-tracked frames before a true-silence hole carry `shapeBreak` ≤ 0.25 with energy sustained ≥ 0.85 across it. Depth's meaning is positional — in-span deep = click, but tongue damping is progressive so at the hole's entry it leaves TWO deep tracked frames where an impulse abrupt enough to blank tracking gets at most one (down-to-the-third's kick: −0.18 preceded by 0.99); the two-deep-frame Blue Monk thump is fenced off by the branch's silence gate instead (its hole is warmup-bridged). A FOURTH short-gap acceptance — **stop-and-hold** (`RE_ARTICULATION_GAP_BAND_STOP`, the 2026-09-09 blue-note-drop tongue ON the beat-3 click): the instrument-band floor (`bandRmsMin`) falls ≤ 0.75× ACROSS a true-silence hole — click-immune, a click only ADDS energy — AND the level 100–400 ms after tracking resumes holds ≥ 0.75× the pre-hole level; a note decaying under a click passes the first (floors down to 0.16) and fails the second (0.05–0.54), a click on a held note fails the first (0.83 on the down-to-the-third kick is the nearest impostor). Once the gap pass has marked a hole, the clarity dip-and-recover tier defers on it — one articulation, one onset: its recovery anchor landed 66 ms after the gap anchor on the 2026-05-20 take, past the 60 ms dedupe, and the sliver became a fourth note. Upstream of the tiers, two 2026-09-09 rules: `validateOnsets` credits an onset only with readings whose analyser window (`ANALYSER_WINDOW_SECONDS`, 93 ms) ends before the NEXT onset — a pre-armed capture holds the downbeat click the player enters on, and the first note's own attack readings used to validate the click's onset into a 177 ms phantom head (blue-note-drop: a correct take saved as 2 of 3); and `segmentNotes` RESPELLS a sub-150 ms note an octave from the longer note before it — when the note after does not continue that octave and the raw frequencies inside the sliver plus one analyser window past its end read the neighbour's fundamental on ≥ 25% of frames — rather than deleting it: a re-tongued G3 speaks on its 2nd harmonic for ~70 ms (climb-to-five 2026-09-09, h1/h2 0.15–0.21), and the shape tier plus a worklet onset 78 ms late had cut that transient into a G4 note (the stabiliser's 3-frame confirm inertia is why the sliver's own frames carry only one fundamental pick). Inside a segment, an **octave-cracked attack** folds into the note it cracks into (`isUnconfirmedOctaveCrack`, 2026-09-16 sharp-9-flat-9-dom: a tenor D4 spoke as D3 for ~110 ms with no attack at the switch, and replay emitted D3 @0.093 + D4 @0.283): the head sub's octave was never CONFIRMED — fewer than `OCTAVE_CONFIRM_FRAMES` frames past warmup whose RAW pick is its pitch (warmup frames are raw passthrough; the two frames the confirm inertia holds after the raw pick moves are not audio) — and the raw pick then sat in the neighbour's octave on more frames than its own. Frames, not span: the span ran from the downbeat click's onset, 50 ms before the horn, to the reported switch (190 ms, past the 150 ms rule), and live's window-end stamps add a whole analyser window.   **Ghost notes (2026-09-16, sharp-9-flat-9-dom — a Deep Practice take saved 6 of 9 with every ghosted C swallowed by the Ds).** A ghosted note reads under the 0.80 clarity threshold for its whole length (0.54–0.76 there), so the confident stream holds only a HOLE. `detectFrame` returns in-range frames in [`WEAK_CLARITY_FLOOR` 0.5, threshold) as `weakReading` — raw pick, never through the stabilizer — and the detectors keep them on a SIDE channel (`getWeakReadings()`, `ReplayResult.weakReadings`, `trimToPerformance`'s 5th argument), never in the readings. `findGhostNotes` turns a plateau inside a 75–400 ms hole (≥ 3 consecutive frames within ±0.35 st, folded into the line's register, ≥ 0.75 st from BOTH flanking notes ignoring octave, ≥ −20 dB of the louder, at most 2 absorbed confident frames on its own pitch) into a `ghost: true` note at its MEASURED pitch, and `segmentNotes`' 10th argument carves it in last. The flag is informational: a ghost is scored by its nearest semitone like any note — Andy's call (2026-09-16), "if a note is that far out of tune, it should count as incorrect" — so two of the reference Cs (C + 62/+ 70 ¢) score as C#. Across the corpus only the three reference Cs qualify — every other hole's plateau sits within 0.72 st of a neighbour — pinned per fixture.   **Third-harmonic (twelfth-up) locks (2026-10-17, third-walks-back-to-root — a held D3 saved as D3 · A4 · D3, two charged extras, 0.657 "fair").** As a low note swells its 3rd harmonic can carry ~10× its fundamental (440 Hz at 10× the 147 Hz D3 there) and McLeod picks it for a stretch at clarity 0.9; the octave stabilizer only questions ±12/±24 jumps, so a 19-semitone one passes, and `splitByPitchChange` cuts the held note in three — no octave pass reaches a 19-semitone neighbour. `isTwelfthUpLock` (pitch-frame.ts) flags a frame in 240–600 Hz when g = f/3's other partials (g, 2g, 4g, 5g — non-harmonic bins for a real note at f) carry ≥ 0.2 of the f + 2f energy AND ≥ 5× the half-series bins between them (1.5g … 4.5g): broadband attack energy lifts both sets alike (corpus: ≤ 3.2× on every in-band frame over the first ratio; the lock 11–37×). The flag means "fold a twelfth down from the pitch this frame REPORTS", so it is never set on a frame the subharmonic pass or the stabilizer moved (`octaveUp` keeps only the stabilizer half of that guard since 2026-10-24 — see below). `foldTwelfthUpLocks` acts on the SUB-segment (≥ 60% of ≥ 3 confident frames flagged), before the octave collapse and `mergeConsecutiveSameMidi` — that ordering is what reunites a mid-note lock with the note around it, keeping its own attack and release; only the frames on the locked pitch move and their raw `frequency` is kept. The same fold runs ONCE MORE where segment boundaries are born: live ear training has no worklet onsets (the worklet never attaches), so `extractOnsetsFromReadings` derives them from the readings and cut the held note at the lock's two edges BEFORE any sub-fold could run — and with no attack evidence `segmentNotes` returns early, so nothing rejoins the pieces; `foldTwelfthUpLockRuns` folds lock RUNS on the stream under the same gate before the extractor reads it (CodeRabbit on PR #280, 2026-10-16; the corpus is unchanged). A rule that says "this MIDI change is not a note change" must live in both places or it only works in a test that passes onsets. The scan now folds lock runs on its stream first (`foldTwelfthUpLockRuns`); only `midi`/`midiFloat` move, so every tier measures what it did, and the corpus segments byte-identically. The take carries every per-frame flag, so this one is pinned on the saved-readings path too.

  **Timbre-switch tongues (2026-10-17, blue-note-step-up — a tongued repeated D3 saved as one 1.2 s note, 2 of 3, 0.667).** The tongue left no reading gap, no tongue noise, a 6-cent sag and a 15% / 20 ms notch inside a swell (window RMS never dipped), and the reed reset spread over three cycles, so `shapeBreak` stayed at 0.991.   **Ear-training arms the capture before the user plays.** `capture-window.ts`. The pitch detector, onset worklet, MediaRecorder and transport snapshot all start when the listening window opens — a capture armed by its own first note can never hold that note's attack, because the trigger is a confident pitch reading and that needs most of a 4096-sample analyser window (~93 ms) of the note first. `trimToPerformance` then discards the reaction-time lead-in, keeping a fixed `PERFORMANCE_PREROLL_SECONDS` (0.35) ahead of the first PERFORMANCE reading — not the first *confident* one: McLeod clarity is amplitude-invariant, so the metronome's ringing tail (a pure ~271 Hz line at −58 dBFS decaying ~400 ms after each click, 2026-09-03 tonic-turn take) reads as clarity-0.9 pitch 35–40 dB under the notes, anchored the trim 1.2 s early and became three phantom notes that DTW matched against the expected line (a correct take saved as try-again, 1/4 hit). `dropSubFloorRuns` runs first: a RUN of readings (split at holes > `READING_RUN_GAP_SECONDS`, 0.1) whose peak never comes within `PERFORMANCE_FLOOR_DB` (−30, relative because the mic runs with auto-gain off and a bleed artefact scales with the monitor while played notes don't) of the take's loudest reading is dropped wherever it sits — leading, mid-rest, trailing; a run that reached performance level keeps every reading, decay tail included, so the re-articulation tiers see the evidence they were tuned on (real decays are tracked to −46 dB) and the corpus is byte-identical. The pre-roll is bounded on BOTH sides: it must exceed the ~190 ms detection lag it undoes, and it had to stay under the ~250 ms where the DTW started to flip — `rhythmDistance` saturates at one beat, and re-scoring the fixture corpus showed 12 of 21 takes change grade between a 0.25 s and 0.5 s lead-in (always takes with a missed note, where rhythm is what decides WHICH note went missing); since 2026-10-06 the aligner removes the constant delay before pairing, so that bound no longer holds the pairing and the value stays for the frame the corpus was tuned in. The trim is a pure function of the capture so the live path, the authoritative blob rescore and /diagnostics each re-derive the same offset instead of persisting one (/diagnostics trims ear-training recordings ONLY — `diagnosticsReplayFrame` replays a lick-practice take untrimmed, `captureTrimSeconds` 0, over its close path's `durationThroughLastReading` rather than the blob's length, because lick practice never trims and has no rescore); `recordingTransportSeconds` keeps describing the blob's first sample and every consumer adds its own offset. Recordings captured before pre-arming have their first reading at ~0, so the trim is a no-op for them. Note lick-practice solves the same problem differently — one continuous detector for the whole session, windows sliced by `readingsStartCount` — because its windows open on a bar boundary, not on the user's entry. Record-a-lick (`/licks/record`) is the third variant: the entrance is SCHEDULED (bar-3 downbeat after a 2-bar woodblock count-in), so the detectors run from the top of the count-in and `rebaseToAnchor` re-origins the finished take on the anchor — the context time Tone hands the bar-3 `transport.schedule` callback (the audible downbeat, not the ~0.1 s-early callback time). No reaction time means no preroll; instead `ANCHOR_EARLY_TOLERANCE_SECONDS` (0.15 — above attack-transient scale, below one beat at 240 BPM so the last count-in click never survives) keeps slightly-early events at negative times and the quantizer clamps them to beat 0. ### Key design decisions

**Practice-phase colours are two aliases.** `--color-phase-play` (brass) and `--color-phase-listen` (on-air red) in app.css: the user PLAYS in brass and LISTENS in red because red reads as "stop". Every listen/play indicator (phase tab + lamp + recording ring in `UpcomingKeysDisplay`, `PhaseCueBar`, ear-training's status line, tune practice's head/your-turn captions and open window, record-a-lick's live readout) uses the aliases; stop/record BUTTONS, the console LED and rocker legend stay on `--color-onair`; decorative brass (labels, rules, the all-clear halo) stays `--color-brass`. `design-token-consistency.test.ts` pins the mapping and sweeps the phase surfaces for raw palette tokens.

**Concert pitch canonical.** All MIDI note numbers, scale data, and lick data use concert pitch internally. Transposition to written pitch (Bb/Eb instruments) happens only at display time in `phraseToAbc()` (notation.ts) and `concertToWritten()` (transposition.ts).

**Fraction-based rhythm.** Durations use `[numerator, denominator]` tuples (e.g., `[1, 8]` = eighth note, `[1, 12]` = triplet eighth). Conversion to seconds happens only at audio scheduling time.

**DTW scoring with latency correction.** Dynamic Time Warping in `alignment.ts` aligns expected vs detected note sequences in two passes: the first, on the raw recording clock, reads the constant delay off the PITCH-MATCHED pairs (the median over every pair is pulled towards the shifted pairing it came from), the second pairs with that delay removed; an unpaired note costs `SKIP_COST` 1.5, so a stray plus a miss (3.0) no longer outweighs three wrong pitches (2026-10-06 — Honeysuckle Rose: a cracked attack saved as its own note shifted every pairing after it, three played notes marked wrong, because the live clock runs ~0.2 s behind the written line and that is an eighth at 162 BPM). The scorer then subtracts the median timing offset across the final pairs, absorbing constant human/detection latency.

**Local-first.** All writes go to localStorage/IndexedDB first. Supabase sync is optional and runs in the background. User data survives offline; page loads still need the network (no service worker — see tech-stack.md, "Installable web app").

**Shared AudioContext.** Tone.js and smplr share one AudioContext (via `audio-context.ts`) so Transport scheduling and sample playback stay on the same timeline.
**One voice per instrument.** `audio/instrument-voices.ts` `INSTRUMENT_VOICES` (keyed by `InstrumentId`, so a new instrument won't type-check without one) holds each demo horn's samples, SoundFont fallback, warmth-lowpass ceiling (follows the sax register: tenor 4.5k, alto 6k, soprano 9k) and pitch vibrato. Each sounding note randomly chooses straight, two-second-delayed narrow, gradually widening through release, or immediate narrow vibrato that ends early; notes shorter than 0.6 s stay straight and the previous width remains the ceiling. `playback.ts` keeps no per-instrument branches.
**Sentry initialises once per process.** `src/instrumentation.server.ts` guards `Sentry.init` with `isInitialized()` — do not remove it as redundant. Production loads the file once via `--import`, but `vite dev` loads it through `ssrLoadModule` on EVERY request, and every wipe of the SSR module graph re-evaluates it in the same long-lived process: a `vite.config.ts` / `.env` / `svelte.config.js` restart, an edit to the file or its `$lib/util/sentry-filters` import, and ANY `tsconfig.json` add/change/unlink under the project root — Vite 8's `reloadOnTsconfigChange` calls `invalidateAll()` on every environment, and the worktrees under `.claude/worktrees/` sit inside the root, so every parallel session's checkout counts (ordinary route/hook/component edits, `svelte-kit sync` and dependency discovery do not). Sentry's `init` is not idempotent: each call subscribes another `child_process` diagnostics-channel listener, another `uncaughtException`/`unhandledRejection`/`beforeExit` handler and, on macOS, spawns another `sw_vers` whose child carries every subscriber's `error` listener — the 13-hour dev server that printed `MaxListenersExceededWarning: 11 error listeners added to [ChildProcess]` (2026-09-10) had initialised 48 times, read live over the inspector protocol (`process.getBuiltinModule('node:diagnostics_channel').channel('child_process')._subscribers.length`). Measured per trigger with a `--require` preload counting the subscriptions; the guard holds the count at one through all of them. Pinned by `tests/unit/server/instrumentation-server.test.ts`. An edit to the Sentry options in dev needs a dev-server restart. `vite preview` is NODE_ENV=production too, so the server's `beforeSend`/`beforeSendTransaction` refile anything about a request to a loopback host under development (MANKUNKU-1V), the twin of the client's hostname check.


### State management

State modules in `src/lib/state/` use Svelte 5 runes (`$state()`, `$derived()`, `$effect()`), not Svelte 4 stores. Key modules:
- **session.svelte.ts** — Single-phrase practice session (not persisted)
- **settings.svelte.ts** — User preferences (persisted to localStorage). Default swing is 0.62, not straight — deliberate: demos, the scoring grid and record-a-lick review playback all follow the knob, and exactly 0.50 doubles as `resolveBackingSwing`'s "band follows the tempo curve" sentinel, so the shipped default pins the band to the knob and dialing back to 0.50 restores the tempo curve. `metronomeVolume` (default 0.5) is a mix position — `METRONOME_TRIM` applies underneath in audio/metronome.ts.
- **progress.svelte.ts** — Session history + adaptive state (persisted, bounded to 100 entries)
- **history.svelte.ts** — Long-term daily progress summaries for calendar heatmaps and period comparisons (persisted, survives the 100-session prune window). **Derive-on-write**: summaries are a pure derivation of two source-of-truth tables (`progress.sessions` and `lick-practice-sessions`); every write to either source calls `recomputeDailySummary(date)` so divergence is impossible and replaying a write is a no-op. The exception is the `ComplexitySnapshot` fields (`pitchComplexity`/`rhythmComplexity`/`tonalMastery`/`scaleLevels`) — point-in-time values NOT derivable from the sources, supplied only by ear-training's `recordAttempt`: every recompute without a fresh snapshot preserves the stored ones, and `mergeWithExisting` keeps a defined value over an absent one because a cloud row mapped from NULL columns carries them as present-but-undefined, which a plain spread would erase (`scaleLevels` feeds the per-scale trend panel (click-to-expand, in flow) on /progress via `state/scale-trend.ts`, which backfills pre-snapshot dates by replaying surviving sessions through `processScaleAttempt`, anchor-shifted to the first known real level). `practiceMinutes` is NOT a function of the session counts (it was `(ear + lick attempts) × 2`, which read a six-key lick session as twelve minutes): the lick side is the log's own `report.elapsedMinutes`, summed by SESSION via `sumLickPracticeMinutes` because `splitReportByProgression` copies that session-wide field onto every per-progression slice, and only the ear side is still estimated (`EAR_MINUTES_PER_ATTEMPT`, 0.5 — `session_results` records no duration and the ear-training page's active-practice clock is page-local). `mergeWithExisting` and the cloud reconcile take the MAX of the two sides' minutes, so days written under the old model keep their figure rather than being restated, and the reconcile's push check tests minutes in their own right since equal counts no longer imply equal time.
- **licks.svelte.ts** — Search state for the Licks page (not persisted, exports the `licks` rune). The /licks route is now focused on the user's *own* book — three derived sections (`needsSetup`, `practiceSet`, `otherLicks`) over user + adopted-community licks; the curated ear-training catalog isn't surfaced here. Category/difficulty browse filters were retired with the refocus; the remaining filters are search and a progression filter (`licks.progressionFilter`), which narrows to licks carrying the matching explicit `prog:*` tag via `getProgressionTags`.
- **lick-practice.svelte.ts** — Multi-key lick-practice flow: progression plans, per-key results, tempo adjustments, gradual key unlocking. Advancement gates: `KEY_PROFICIENT_THRESHOLD = 0.90` (green tier — counts toward unlocks and tempo bumps), `KEY_FLOOR_THRESHOLD = 0.75` (a single key below this blocks tempo *increases* and unlocks; decreases still apply), yellow band 0.75–0.89 (passable but doesn't earn). Tempo moves once per lick per session by `computeAutoTempoAdjustment(avg)`: +2 at ≥ 0.95, +1 at ≥ 0.90, −1 at ≥ 0.75, −3 below — except on an unlock session, which skips the delta and drops the tempo 10% instead (`tempoAfterKeyUnlock`, rounded, clamped at MIN_TEMPO): the gate only opens on strong sessions, so the new key would otherwise arrive faster than the tempo that earned it. Each unlock requires avg session score ≥ 0.90 AND newest-key `passCount` ≥ `UNLOCK_PASSES_REQUIRED` (3) AND no floor failure; keys unlock in KEY-SIGNATURE order as the player reads them (`planUnlockedKeys(ramp, n)` in `music/key-ordering.ts`, `UnlockRamp` from `lickUnlockRamp(lick, instrument)`/`trickUnlockRamp`; 2026-10-16): the entry key first, then fewest written sharps/flats, the sharp key before the flat on a tie — a minor lick counts its relative major's signature (G minor ramps G, A, E, D, …), and a tenor's ramp differs from a concert player's because written pitch decides. Three start paths share the engine: **standard sessions** pin to one progression; **Daily Practice** (`startDailyPracticeSession` / `buildDailyPracticePlan`) rotates across every progression the user has `prog:*` tags for, picks each lick's least-recently-practiced compatible progression via `pickProgressionForLick`, and the post-session writer splits the report by progression so the least-recently-practiced lookup stays correct across mixed sessions; **single-lick Deep Practice** (`startSingleLickSession`, launched from the Practice button on a lick's detail page) drills one lick through its currently-unlocked keys only and **derives its progression from the lick's own `prog:*` tags** rather than `config.progressionType` — fixes the major-lick-over-minor-vamp bug — and refills the rotation when every unlocked key clears ≥ 0.95. **Deep practice runs its own tempo rule, entirely in session state** (`lick-practice-rotation.ts`): it opens at `deepPracticeStartTempo` (2% under the lick's stored tempo, `Math.min(t - 1, …)` so rounding can't make the ease-in a no-op) and bumps by `nextCycleTempo` — `config.tempoBumpPercent` (default 1) of the *current* tempo, rounded UP because 1% below 100 BPM would otherwise floor to zero. ## OMR subsystem (`omr/` — Python, standalone) + hybrid PDF import

**Hybrid PDF import**: `pdf-glyphs.ts` and the glyph rhythm/form/layout modules read supported SMuFL/vector notation directly; `pdf-notation-fonts.ts` and `pdf-legacy-text.ts` adapt exact Inkpen2 families without reinterpreting prose. `pdf-tuplets.ts` resolves multiple printed triplets jointly with bounded ambiguity checks. `pdf-repeat-dots.ts` supplies compact pixel evidence for repeats, excluding staff ink; `pdf-embedded.ts` shares the fusion policy between upload and evaluation. Complete embedded measures bypass optical melody recognition and survive partial provider failure. `pdf-noteheads.ts` selects thin-line stem/ring or thick-line shape detectors by measured staff thickness; `pdf-review-image.ts` adds bounded narrow source-only head panels for independent review, retaining the complete measure for accidentals and rhythm. `pdf-bar-review.ts` and `pdf-notation-review.ts` own provider-independent review orchestration and two-reading acceptance for suspicious dotted rhythms, untied repeated notes and independent note-count disagreements. `pdf-harmony-reading.ts` validates indexed harmony; the adapter can recover up to eight failed measures from original crops with concurrency two. `pdf-pitch-reconciliation.ts` retains individually corroborated corrections only with complete head evidence and matching timing/rest alignment (tolerating decimal rounding); unresolved notes remain review warnings. Ordinary pitch-review disputes retain original accidentals. `pdf-accidental-review.ts` compares two symbol observations with independent note counts and complete pitch alignment. This pass is advisory only: same-model agreement misread naturals in the held-out raster benchmark, so it must never rewrite pitches. The symbol adapter is bounded to two concurrent one-minute calls and skips OMR harmony-only requests. Opening source crops retain leading accidental ink. `PdfSourceReview.svelte` compares original measure crops with the editable draft without persisting image data in the tune. `pdf-recognition.ts` defines the provider-neutral `SystemRecognizer` seam; `server/pdf-import/` adapts Anthropic with separate header, melody, and harmony passes and shared strict JSON envelope decoding. `omr-transcription.ts` handles untrusted `.omr.json` shape conversion, while `omr-quality.ts` gates melody coverage on exact measure alignment and content quality. Accepted OMR skips melody calls; scans still need harmony recognition. Failed lines retain empty bars and no key vote. `pdf-accuracy.ts` and `scripts/evaluate-pdf-import.mjs` provide fresh precision/recall measurements and strict targets; historical saved-fixture floors are not release approval. See `docs/omr/pdf-import-accuracy.md` for interfaces, deadlines, commands, and limitations.

A uv-managed Python 3.12 project (own `pyproject.toml`/`uv.lock`/`.venv`) that transcribes lead-sheet PDFs/images to symbolic notation — the future replacement for direct vision-LLM reading in PDF import. **Nothing in the app calls it** — the PDF import page only accepts its `.omr.json` OUTPUT, produced locally — and `/api/tune-parse` is untouched.
